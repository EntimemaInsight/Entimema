# Universal Income Statement interpretation — P0 audit and design

## Architecture audit (before)

The current implementation already authenticates before multipart parsing, inspects one in-memory upload, supports XLSX/XLSM/CSV through SheetJS and extracts text from PDF. Workbook sheets are classified independently and contiguous period columns are bounded. Extraction, structural classification and semantic mapping, however, live together in `extraction.ts`; mapping is primarily a flat regex allowlist. Validation contains period-specific revenue, gross-profit, operating-profit, pre-tax and bottom-line equations. Reviews are grouped by source row and replay recomputes controls/readiness. Persistence is owner-scoped with optimistic revisions, signed run integrity, append-only repository events and a validated snapshot written on transition.

Analysis lived only in React component state. It was cleared when opening a persisted run, but not on file selection, execution, statement re-execution, review mutation or failure. Consequently, a valid analysis object from an earlier run remained renderable beside a later review-required run. Analysis/report endpoints checked ownership and validated status but accepted no expected revision, selected statement, schema or snapshot identity. The classifier has a server-only OpenAI Responses integration; Financial Intelligence had a label-only injected fallback and no deployed semantic resolver configuration. Uploads are capped at 4.5 MB; functions use the Next/Vercel request lifecycle and no OCR service exists. Existing fixtures cover comparative workbooks, XLSM formulas, monthly/annual sheet separation, authorization, persistence, analysis and the unchanged PDF renderer. No company/cell rule was found; some sheet-name classification signals remain as candidate evidence, not semantic mappings.

## Architecture after

The v2 contract adds a neutral observed-document adapter contract, independent candidate/structural types, a hierarchical ontology, centralized confidence policy, relationship graph, bounded semantic resolver and owner-scoped mapping-memory contract. Spreadsheet adapters preserve cells, coordinates, formula, number format, style/indentation, merged ranges and hashes. PDF is explicitly text-only and safely warns on image-only input. Existing extraction remains operational while these independently testable boundaries are introduced incrementally.

Ontology matching is anchored and bounded. Candidate confidence combines semantic, structural, equation, sign, context and scoped-history scores; contradictions block selection. Arithmetic evidence never changes source values or signs. The AI boundary can only select a supplied canonical concept or return unresolved, receives no financial table/values, validates output, and cannot determine readiness. A production mapping provider is intentionally not enabled: deployment would require a separate server-only model name/API configuration, retention review and provider implementation. Unavailability therefore becomes review.

Analysis/report requests now carry and server-verify owner-scoped run ID, revision, selected candidate, signed validated-state hash and canonical schema version. Client-derived state is cleared on session identity, file selection, execution, run opening, statement rerun, review mutation and failures; rendering additionally checks the returned analysis identity. Non-validated runs remain locked.

## Evaluation and limitations

`npm run evaluate:financial-intelligence` emits reproducible per-document and aggregate results with explicit numerators/denominators. The legally safe corpus has one development, one holdout (a minimal sanitized Rieter-shaped annotation, not source content), and one adversarial document spanning the requested taxonomy. Rieter expectations remain two periods, 30 rows, 60 values, scale 1,000,000 and honestly unresolved currency. The corpus is far too small to establish launch thresholds, so commercial universality is **UNPROVEN** regardless of point estimates. PDF table reconstruction remains unsupported where reliable structure cannot be isolated; scanned/handwritten/password-protected/corrupt/non-English documents must resolve to review/unsupported rather than validation. Persistent mapping-memory storage is a defined owner-scoped interface but requires a future migration before learning is enabled.
