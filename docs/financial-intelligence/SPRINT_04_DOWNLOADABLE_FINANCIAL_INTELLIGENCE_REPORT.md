# Sprint 04 — Downloadable Financial Intelligence Report

## Current-state audit

Sprint 03 already placed the successful `Result` contract in client state and rendered its executive summary, KPI statuses, evidence-linked findings, and verified statement. The execution route is a Node.js, authenticated, non-cached POST. There was no PDF writer or download infrastructure in the application dependencies; `pdf-parse` is input-only. The workspace is authenticated at the page boundary and execution endpoints independently authorize requests. Deployment is the Next.js Node runtime.

The smallest reliable design is therefore a synchronous server-side PDF renderer and one authenticated POST route. The browser sends the successful in-memory result it already displays; the route validates that presentation payload, returns PDF bytes immediately, and stores nothing. This avoids source-file access, public report URLs, browser print output, and a large reporting subsystem. It also keeps document-generation code out of the client bundle.

## Architecture and contract reuse

`backend/reports/financial-intelligence-report.ts` is a presentation adapter. `parseReportResult` validates the existing statement and analysis shape. `createReportModel` is deliberately a lossless projection of `Result`: the summary, KPI objects, findings, line objects, source labels, periods, values, aggregation roles, currency, scale, and verification count are reused. Only display formatting, page layout, the fixed verification note, generation date, and safe filename are added.

The renderer writes an A4 PDF using built-in PDF Type 1 fonts, so no new service or runtime dependency is required. It paginates before the footer, repeats the income-statement header on continuation pages, right-aligns fixed-width numeric columns, formats negatives consistently with parentheses, and distinguishes contract-provided subtotals/totals. It performs no arithmetic. The report endpoint uses `authorizeExecution`, `Cache-Control: no-store, private`, attachment disposition, and MIME hardening.

The Download PDF action exists inside `FinancialIntelligenceResult`, which is mounted only when the execution has returned a successful result. Failed or cleared results therefore have no action. The button reports progress and a recoverable error. The downloaded filename follows `Entimema_Financial_Intelligence_<Entity>_<Period>.pdf` with bounded ASCII sanitization.

## Report structure

1. Header: product, entity, statement type, periods, currency, scale, verification statement, and generation date.
2. Executive Summary: exact existing summary.
3. Key Performance Indicators: every existing KPI and status, including the Sprint 03 sign-change wording and clean unavailable/not-meaningful labels.
4. Key Findings: the first five existing evidence-linked findings, retaining title, statement, and severity.
5. Verified Income Statement: exact source labels, source periods, and verified numeric values.
6. Source / Verification Note: fixed non-technical verification statement and verified-value count.
7. Footer: restrained Entimema identification and page X / Y.

Raw source references, model identity, hashes, timings, architecture, and AI-call metadata are excluded.

## Integrity and acceptance

Focused tests cover the controlled profitable P&L, Rieter loss/sign-change result, and missing/unavailable-KPI result. For all three, the report model is deep-compared with the successful result contract for summary, KPI objects/statuses/values, findings, statement lines/values, and metadata. Generated bytes are opened with the existing PDF parser; authored text and every statement number must be extractable, while technical metadata and invalid numeric tokens must be absent. Separate checks cover sign-change language, unavailable states, invalid/non-finite rejection, safe filenames, A4 page structure, and multi-page continuation headers.

No report test or production report path imports the calculator, observations/interpreter, readers, source binder, verifier, Finance Domain, Airtable, or OpenAI. Report generation makes zero AI calls; total execution remains exactly the single frozen extraction call. No engine file, prompt, provider configuration, concept mapping, KPI formula/status, verification method, or analysis methodology is changed.

## Security and privacy

Generation is request-scoped and in memory. The uploaded file is not reread and financial data is not newly persisted. The endpoint is authenticated, responses are private/non-cacheable attachments, and no addressable report resource is created. V1 intentionally does not retain report history or provide share links.

## Known V1 limitations

- PDF text uses the built-in Helvetica family and safely substitutes glyphs outside its supported print character set; the original contract data remains unchanged in memory.
- Extremely long source labels wrap within the label column to protect numeric columns and may increase page count.
- V1 includes a concise verification note rather than a potentially lengthy evidence appendix.
- Reports are generated from the currently successful browser result and are not stored for later retrieval.
