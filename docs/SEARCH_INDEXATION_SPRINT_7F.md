# Sprint 7F — Search indexation baseline

Audit date: 2026-08-11

Canonical production origin after Sprint 7F: `https://www.entimema.net`

Scope: all 21 public, indexable URLs generated by the application

## Audit method and boundary

The production build was inspected route by route for HTTP status, rendered canonical, robots directives, title, H1 and JSON-LD. Sitemap and robots output, configured redirects, invalid Resource slugs and a generic missing route were also tested. The live host was checked separately: the apex host redirects permanently to `www`, while `www` returns 200. Sprint 7F therefore aligns canonicals, sitemap URLs, robots host and schema URLs with `www`.

Search Console performance and coverage data were not available to this repository audit. No impressions, clicks, rankings or indexation decisions are inferred.

## Sitemap, robots, redirects and missing content

- Sitemap contains 21 unique URLs: six core/index/trust pages, ten service routes and five published Resources.
- No drafts, redirect sources, 404s, utility/API routes, legacy Bulgarian routes or duplicate URLs are included.
- Every sitemap destination returned 200 in the production build and emitted a matching canonical.
- `robots.txt` allows legitimate public crawling and references the canonical `www` sitemap. It does not expose internal paths or add arbitrary restrictions.
- Invalid Resource slugs and an arbitrary missing route return 404, not soft 404 content.
- Six configured legacy routes return one-hop 308 redirects: `/insights`, `/services/financial-architecture`, `/services/risk-management`, `/services/data-ai-automation`, `/services/finance-transformation`, and `/services/cfo`. No chains or loops were found.
- No public Bulgarian route or Bulgarian search metadata is present.

## Structured data and entity consistency

Resource Article data matches visible titles, real publication dates, canonical URLs, author identity and publisher. BreadcrumbList reflects the visible Resources hierarchy. Homepage Organization and WebSite data now establish the same Entimema name, canonical `www` origin, real logo and visible founder relationship. No reviews, ratings, clients, credentials, external profiles or `sameAs` destinations are fabricated. Additional schema types were not added where they would not clarify a real entity or visible page.

## SERP readiness

All 21 titles are unique, concise and aligned with their H1/page purpose. Descriptions are unique across the commercial owners and five Resources; they describe relevance without keyword stuffing. Primary navigation, service/index pages, Resources discovery, footer links and self-consistent canonicals provide a clear hierarchy suitable for Google's interpretation. Sitelinks remain algorithmic and cannot be configured or guaranteed.

## Performance, mobile and search-facing trust

The production build has no third-party analytics/tag-manager client script. Resource covers are code/CSS-native rather than heavy editorial images. Rendered pages were checked for horizontal overflow and core landing-page usability at desktop and mobile widths. Resource titles, article copy, TOC, analytical figures, related links, capability transitions and the Contact form remain usable. No hydration warning or clear layout-shift regression was observed. Public metadata is English-only and does not expose fictional client identities.

## Deferred decisions

- Confirm Search Console property access and data inside Google's interface; repository and DNS inspection cannot establish account ownership or report history.
- Do not add behavioural analytics or contact attribution until a specific vendor, consent model, retention policy and Privacy-notice update receive approval.
- Evaluate cannibalisation, Bulgarian demand and international query families only after sufficient first-party data exists.
