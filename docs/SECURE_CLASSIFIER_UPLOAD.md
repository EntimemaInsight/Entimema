# Secure Document Classifier uploads

The active production classifier path is authenticated multipart upload to the run route for the existing PDF, XLSX, XLSM, XLS, CSV, TXT, and DOCX intake formats. Vercel's documented 4.5 MiB limit applies to the complete request body, not just the file. A 4,718,592-byte file would exceed that platform boundary after multipart framing. The safe fixed operational file boundary is therefore **4.5 MB (4,500,000 bytes; approximately 4.2915 MiB)**, leaving 218,592 bytes for browser-generated multipart headers and boundaries beneath the **4,718,592-byte request boundary**. The file is inspected and processed in Function memory and is not persisted. The browser and server share these constants from `lib/document-classifier-upload.ts`.

Private S3-compatible direct-upload modules are preserved for a future infrastructure sprint, but are inactive: the workspace does not request a grant, the run route does not accept an upload reference, and the grant route returns a controlled `410 UPLOAD_FAILED` response after authentication. This prevents missing storage configuration from affecting the active classifier and avoids implying that direct upload is available.

Configure `DOCUMENT_UPLOAD_S3_ENDPOINT`, `DOCUMENT_UPLOAD_S3_REGION`, `DOCUMENT_UPLOAD_S3_ACCESS_KEY_ID`, and `DOCUMENT_UPLOAD_S3_SECRET_ACCESS_KEY` in Preview and Production. The endpoint must be HTTPS and name a dedicated bucket with all public access blocked, encryption at rest enabled, CORS restricted to the application origins and `PUT`, and a lifecycle rule deleting `classifier-temp/` objects after 24 hours. Immediate deletion is attempted after success and every controlled failure; the lifecycle rule covers interrupted Functions. Credentials require only object create/read/delete access under `classifier-temp/`. Never expose them with a `NEXT_PUBLIC_` prefix.

`DOCUMENT_UPLOAD_REFERENCE_SECRET` signs browser-held references; if omitted, `AUTH_SECRET` is used. These values are not required by the active multipart path. No public-storage fallback exists.
