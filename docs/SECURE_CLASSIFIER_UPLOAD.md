# Secure Document Classifier uploads

The classifier uses one direct-upload path for the existing PDF, XLSX, XLSM, XLS, CSV, TXT, and DOCX intake formats. The browser requests a five-minute, actor-bound grant, uploads with a presigned `PUT` directly to a private S3-compatible bucket, and sends only an opaque signed reference to the run Function. The Function downloads with a separately signed request, checks the declared and actual size, extension, MIME, and signature, runs the existing classifier, and deletes the object in `finally`.

Configure `DOCUMENT_UPLOAD_S3_ENDPOINT`, `DOCUMENT_UPLOAD_S3_REGION`, `DOCUMENT_UPLOAD_S3_ACCESS_KEY_ID`, and `DOCUMENT_UPLOAD_S3_SECRET_ACCESS_KEY` in Preview and Production. The endpoint must be HTTPS and name a dedicated bucket with all public access blocked, encryption at rest enabled, CORS restricted to the application origins and `PUT`, and a lifecycle rule deleting `classifier-temp/` objects after 24 hours. Immediate deletion is attempted after success and every controlled failure; the lifecycle rule covers interrupted Functions. Credentials require only object create/read/delete access under `classifier-temp/`. Never expose them with a `NEXT_PUBLIC_` prefix.

`DOCUMENT_UPLOAD_REFERENCE_SECRET` signs browser-held references; if omitted, `AUTH_SECRET` is used. `DOCUMENT_CLASSIFIER_MAX_FILE_BYTES` defaults to 20 MiB. Local development requires an equivalent private S3-compatible store and CORS origin. When configuration is absent, grants fail safely with `STORAGE_UNAVAILABLE`; files are never redirected to public storage or the old multipart route.
